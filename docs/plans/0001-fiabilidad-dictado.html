Impacto y límites

Uso

Un fallo de captura se notificará y permitirá volver a pulsar el atajo. El audio de una captura fallida se descartará para evitar transcribir datos parciales como si fueran completos.

Datos y configuración

Sin cambios en TOML, diccionario, modelos ni formatos de audio. Se conserva la interfaz de AudioRecorder.start() y stop().

Desarrollo

Pruebas con flujos de audio simulados, sin GPU, Ollama ni sesión gráfica. Añadir NumPy al entorno de pruebas de CI para ejercitar las matrices reales de audio.

Operación

Conservar la notificación traducida existente para errores de micrófono. Reiniciar el proceso para cargar la corrección; no hay migración.

Fuera de alcance: rediseño visual, cambios de STT/LLM/TTS, reconexión de teclados, nuevas funciones y refactorizaciones generales.

Puerta de producción

  • El portal queda listo para iniciar después de una parada fallida y no se transcribe esa captura.

Comprobación manual en KDE

  1. Con la aplicación corregida, provocar un fallo recuperable del micrófono al iniciar o detener una captura y observar el mensaje de error y la retirada del overlay.
  2. Restablecer la disponibilidad del dispositivo. Pulsar de nuevo el atajo, dictar una frase breve y comprobar que se pega correctamente sin reiniciar el proceso.
  3. Repetir con evdev y con el portal en modo toggle. Confirmar que el primer atajo posterior al error inicia una nueva captura.
  4. Comprobar una captura normal con ambos mecanismos y revisar los logs. Restaurar la configuración temporal utilizada en la prueba.

Si el entorno no permite inducir un fallo de hardware de forma repetible, registrar exactamente qué casos se validaron por simulación y qué comprobación real sigue pendiente.
